# 管理员操作说明

本说明对应新版 `/api/v1` 与小程序内管理页。当前开发和演练使用合成数据；线上仍运行原版本。

## 权限

普通管理员负责学生、社团、导入预览与导出；超级管理员另外负责管理员账号/角色、活动配置与发布/暂停。首次登录先修改初始密码。换届重置由运维在维护窗口通过受保护CLI执行，不是小程序里的日常按钮。

## 开放前

1. 保持活动为草稿或暂停。核对社团名称、总名额、专业限制、地点与介绍；专业限制为空表示不限专业。
2. 添加或导入本届学生。账号建议用文本形式的学号，避免Excel丢失前导零；专业名称须与社团限制一致。
3. 核对预报名：使用稳定数字社团ID，预报名占用总名额，一人只能有一个社团；预报名学生默认不能自行退选；已有普通报名不能直接改成预报名，删除有报名记录的社团会被拒绝。
4. 超级管理员配置完整开始/结束日期时间、是否允许退选及截止时间。页面以北京时间显示；开始时刻允许报名，结束时刻不允许。保存配置会回到草稿。
5. 核对学生数、社团数、预报名和剩余名额，确认后发布活动。服务端会阻止名额不一致、无有效社团、资格冲突或无效时间的发布。

## Excel导入

使用 `.xlsx`，最多5000行，前六列表头按以下顺序填写：

| username | name | major | class_name | password | reserved_club_id |
|---|---|---|---|---|---|
| 合成学号 | 合成姓名 | 专业 | 班级 | 独立初始密码 | 无预报名则留空 |

密码至少10字符、UTF-8不超过72字节，请通过安全渠道分发。文件不能包含重复账号或数据库已有账号；当前导入用于新增学生，不会覆盖原账号。不要把真实名单或密码文件提交到Git。

上传后先等待后台预览任务：查看总行数及前20行预览。校验失败时修正文件重传；预览成功后再确认应用。确认时仍会重新检查活动、账号和名额，并在一个事务中应用；失败不会留下半份名单。任务会显示排队、处理中、预览、完成或失败状态。报名开放期间禁止导入和重型导出。

## 报名中与异常处理

- 开放期间名单、资格、名额和报名结果保持只读。需要维护时，由超级管理员先暂停活动，完成核对后恢复发布。
- 学生提交后显示结果确认中时，先查询自己的报名结果。不要根据页面超时自行修改数据库或增加名额。
- 名额卡片可能短暂滞后，最终报名结果以数据库事务为准；页面显示有余位不代表一定能成功。
- Redis故障时新报名暂停，已提交报名仍可查询。管理人员应记录提示中的请求ID，交由运维排查。
- 退选受活动状态、允许退选开关和截止时间共同约束。预报名不能自行退选。

## 活动结束

确认活动已结束或暂停，再创建导出任务。导出仅授权管理员可下载，包含学号、姓名、专业、班级、社团和报名来源；文件仅任务创建人可下载，按个人资料管理。下一届先执行备份/恢复演练，再按 `OPERATIONS.md` 审核清理范围；不能直接用旧备份覆盖新一届已经产生的报名。

上线前核对微信后台隐私保护指引与实际收集项（账号、报名资料、主动填写的联系方式）一致。头像已改为姓名首字，本版不再采集或传输头像图片。真机验收按用户要求暂缓，模拟器证据不替代真机。
