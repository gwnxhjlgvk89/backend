## 单核对比

使用与 2026-09-28 旧机及 Ryzen 测试机完全相同的原生二进制和 Argon2 动态库；两者 SHA256 均校验一致。选择空闲逻辑 CPU 固定运行，nice=19；每种计算三轮，每轮约 2 秒，轮间休息 1 秒，总实际计算约 12 秒。临时文件已清理，未替换系统库。

| 三轮中位数 | 新机（本次） | 旧机（9月28日历史实测） | 新/旧 |
|---|---:|---:|---:|
| 整数依赖循环 | 3.2304 亿次/秒 | 3.2247 亿次/秒 | 1.002 倍 |
| 固定 Argon2 合成计算 | 50.89 次/秒 | 51.71 次/秒 | 0.984 倍 |

结论：**本次单核实测与旧机基本持平，不是 CPU 性能升级。** 小幅差异不能解释为稳定性能退化；两次测量日期、系统内核与 libc 也不同。Argon2 仅作为历史可比的合成计算，当前姓名密码版本的登录路径不使用该计算。该结果不代表多核或 1500 人业务容量。

原始记录：[single-core.json](../reports/new-production-20260930/single-core.json)，对比计算：[comparison.json](../reports/new-production-20260930/comparison.json)。旧机记录来自仓库历史报告，本次没有重新压测旧正式服务器。

## 公网传输

从新服务器读取不可压缩的随机数据，通过已认证 SSH 发送到接收端并直接丢弃；不创建传输文件、不读取业务数据。每轮目标 64MiB，接收端按实际字节计数，30 秒截止；完整成功后最多运行三轮，轮间休息 1 秒。吞吐含 SSH、协议及路径开销，不等于云平台可保障的带宽。

| 接收端 | 结果 | 范围与解释 |
|---|---|---|
| 独立有线 Linux 发压机 | 93.04 / 93.40 / 90.36Mbps；中位数 **93.04Mbps** | 三轮各完整接收 64MiB，耗时约 5.75–5.94 秒 |
| Mac 公网路径 | 约 **1.11Mbps**，30 秒仅收到约 3.97MiB，触发截止 | 未完成 64MiB；保留失败记录，不作为服务器容量上限 |

Linux 网口 `enp6s0` 协商 **1000Mbps 全双工**，经普通路由直连，测试机负载很低；但这不能证明路由 WAN/运营商下载能力超过 100Mbps。服务器观察到两个 SSH 接收端来自不同公网来源。Mac 路径显著更慢，说明不能把任意单一接收端的结果直接等同于服务器的 200Mbps 规格；本轮未深入排查 Mac 网络。

新机这条已完成测试的公网路径，比旧机历史约 5.13Mbps 的同一 Linux 接收端结果高约 18 倍，明确突破此前约 5Mbps 的瓶颈。但**尚未测满或验证 200Mbps**，也不能据此断言云套餐只有 100Mbps。要验证其上限，需已知接收带宽超过 200Mbps 的独立公网机器及持续传输对照。旧机和新机样本大小、测试日期不同，该倍数仅用于说明已观测的数量级变化。

原始结果：[Linux 下行](../reports/new-production-20260930/bandwidth-linux.json)、[Mac 对照](../reports/new-production-20260930/bandwidth-mac.json)、[发压机网口](../reports/new-production-20260930/generator-link.json)。驱动副本作为文本归档，不包含密码。
