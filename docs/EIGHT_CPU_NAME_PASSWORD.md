# 姓名密码版本：8 CPU / 4GiB 与 4 CPU 对照

本次只增加隔离测试服务的父cgroup CPU时间额度，业务源码保持`547aab2`，配套前端`b5b1d90`；4核基线报告提交为`0fe3c95`。没有部署生产、修改业务代码或网络代理/路由。

后续只读阶段定位见 [COLD_LOGIN_INVESTIGATION.md](COLD_LOGIN_INVESTIGATION.md)，其中进一步区分了建连超时与响应未送达。

## 结论

本轮完成12轮测量，另有一次预建TLS诊断在准备阶段失败。增加到8CPU后，50Mbps提前登录普通报名的服务端P95由4CPU的1.56–1.70秒降至0.51–1.26秒；客户端P95仍为2.21/4.06/2.39秒，第二轮报名和通知超过3秒，未连续三轮达标。三轮均完成1500人流程，所有已提交报名与名额核对一致，无超卖或重复占位。

冷登录仍不达标，50Mbps三轮登录成功数为1238/163/989，超时数为262/1337/511；进入后续流程的人数不足1500。成功返回的服务端登录P95仅0.032–0.108秒，TCP建连与TLS合计P95约9.05–9.14秒，提示端到端等待主要发生在连接链路，不能仅凭此断定CPU是唯一瓶颈，也不能定位到某一具体网络设备。增加CPU额度本身没有消除冷登录失败。

10Mbps提前登录普通报名单轮P95由3.21秒降至2.38秒，1500人全部完成；这是一轮对照，不是三轮稳定验收。网络路径、服务缓存状态和实际到达节奏均限制跨时段比较，不能据此承诺腾讯云8核4GB必定达标。

## 条件

- CPU从`400000 100000`提升为`800000 100000`，MemoryMax保持4294967296（4GiB），MemorySwapMax=0。
- 保持4个API进程、主池15+3/读池4、worker5+5、MySQL连接上限150。各服务内存限制仍合计2948MiB；本轮不调整进程数或连接池。
- 同一Ryzen5900X宿主、测试镜像、ECDSA HTTPS入口、3个独立发压进程、1500名合成学生；每轮测量45秒，使用相同固定合成密码和已改密标记。不包含首次强制改密或连续600秒长连。
- 50Mbps冷登录和提前登录普通报名各三轮，热门100席/最后1席各一轮；10Mbps冷登录三轮、提前登录普通报名一轮；另做50Mbps预建TLS的登录诊断。
- 实际到测试机路由仍为utun8隧道，底层网卡en0；不是已验证的纯局域网。沿用相同流控与驱动，并保留发起调用及请求头实际发出跨度，不能把计划0.6秒当作真实一秒峰值。
- 8 CPU配额不等于8核腾讯云机器；宿主单核/磁盘不同，部分rootless网络辅助进程在配额外。跨时段对照也受网络波动影响，不能把延迟变化全部归因于核数。
