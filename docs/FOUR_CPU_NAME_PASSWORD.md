# 姓名初始密码版本：4 CPU / 4GiB 隔离复测

本次只部署已提交的后端 `547aab2` 到独立测试环境并测量，不修改业务代码、不更新生产。前端配套 `b5b1d90`；独立协议驱动模拟客户端请求，不代表微信真机测量。

## 环境与口径

- Ryzen 9 5900X 宿主，5个测试服务共用父cgroup：`cpu.max=400000 100000`，`memory.max=4294967296`，禁用Swap。4个API进程，主连接池15+3、预留读池4，worker池5+5，总数据库连接预算98/150。
- 每服务内存上限仍为MySQL1152MiB、Redis192MiB、API900MiB、worker192MiB、Nginx512MiB，合计2948MiB。父上限4GiB不表示单个服务可使用全部4GiB。
- HTTPS，独立Mac通过现有网络发压（物理网卡en0，到目标实际路由为utun8隧道，未修改网络设置），3个Python进程各负责500个学生。每轮计划0.6秒集中发起；实际发出跨度另列，超过1秒不能宣称达到了1500人一秒突发。
- 先使用与上次相同的50Mbps出口限制，再测10Mbps。流控只限制测试Nginx容器出口，保留计数器及清除证据。
- 数据是3000个固定合成账号和42个社团，每轮选取1500人。为复现既有驱动，合成账号使用明确指定的测试密码并标记已改密；比较和存储路径与姓名初始密码一致。首次登录强制改密不包含在这些普通登录轮次中。
- 应用22个Python模块逐文件与提交一致；容器构建目录另有19个`._` macOS元数据文件，导致旧驱动按所有`*.py`文件计算的整体指纹不同，详见 `name-password-4cpu4gb-source-verification.json`。实际加载的应用模块无差异。

完整登录场景：冷HTTPS登录→WebSocket/首页初始化→详情→开放时提交→结果确认及名额同步。提前登录场景：准备1500个会话和连接→集中刷新首页/浏览详情→同时报名。热门社团100席、最后1席另做正确性核对。

驱动原始报告中的固定“LAN”描述仅是脚本假设：本轮实际路由经utun8，不能当作已验证的纯局域网链路；下游路径和隧道归属未进一步确认，详见网络证据JSON。

本次CPU额度不等于4核腾讯云服务器：宿主单核、存储不同，部分rootless网络辅助进程在额度外，未模拟公网RTT/丢包。仅凭本机成绩不能决定生产4核配置达标。短时复测也不替代600秒稳定性、全矩阵三轮和真机验收。

50Mbps冷登录三轮，登录成功1357/264/1201人，客户端登录失败143/1236/299人；10Mbps为0/1269/0人成功、1500/231/1500人超时。冷登录实际调用起始跨度1.01–3.35秒，未满足一秒发压门槛，不能授予严格1500人一秒峰值通过。热门100席和最后1席各仅测一轮，正确结果为100成功/1400已满与1成功/1499已满，未完成三轮稳定性验收。

预建TLS后同时登录的对照未形成任何有效轮次：三个分片均在准备阶段GET /health/live时触发10秒TimeoutError。保留completed=false及异常记录，不提供虚构的预建连接成绩，也不据此推导服务器计算能力。

**严格峰值补充核对：** 原脚本ready场景主要以客户端调用开始跨度判定一秒突发，不能等同于请求头实际发出或服务端到达跨度。50Mbps普通报名三轮请求头发出跨度为4.073/7.001/5.123秒；热门100席为2.184秒，最后1席为1.870秒；10Mbps普通报名为5.495秒。因此表中“脚本门槛通过”只代表既有脚本的局部条件，所有场景都不能授予严格1500人一秒峰值容量通过。原始指标保留，未修改业务代码或脚本以改变成绩。

## 证据与复现

结构化汇总：[name-password-4cpu4gb-summary.json](../reports/name-password-4cpu4gb-summary.json)。每个场景保留主报告、三分片逐请求记录、资源配额、流控前后及恢复证据；未保留包含私有环境变量的部署日志。

使用已提交的应用构建测试镜像（生产不参与），保留测试数据库备份，执行`alembic upgrade head`及受保护`club.load_fixture passwords`，将固定合成压测账号标记已改密。证书使用`prepare-test-tls.py`生成的ECDSA测试证书，校验开启。

每个场景先执行`limit-test-pod.py --cpus 4`，读取实际测试pod的CgroupParent，并将其MemoryMax设为4096M、MemorySwapMax设为0；核对实际cpu.max/memory.max。随后用`shape-test-egress.py limit --mbps 50或10 --port 8443`设置测试Nginx出口。

命令骨架：

```sh
.venv/bin/python scripts/load_distributed_journey.py \
  --url https://192.168.100.130:18082 --ca-cert .local/test-ecdsa-ca.crt \
  --ssh gg1214@192.168.100.130 --control /private/tmp/club-test-current-ssh \
  --users 1500 --processes 3 --client-profile connected_first \
  --mode login --scenario uniform --rounds 3 --hold-seconds 45 \
  --report reports/新的唯一报告文件名.json
```

其他场景参数按表中mode/scenario及轮数替换；预建连接诊断使用login_warm。每次完成或失败都保存并清除流控，整组结束恢复原4CPU/3000MiB/禁Swap配置。未修改业务代码或网络代理/路由，未测试生产，未重新执行首次强制改密、600秒长连、3000人超容量或真机验收。

最终收尾：发压进程全部退出，测试服务就绪检查200，出口已恢复noqueue，测试资源恢复原4CPU/3000MiB/禁Swap；已部署的新测试镜像保留。恢复证据为`name-password-4cpu4gb-final-restoration.json`。
