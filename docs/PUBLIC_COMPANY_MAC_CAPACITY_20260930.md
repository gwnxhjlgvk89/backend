提前登录轮，1500 个首页请求在 0.9078 秒内发起，1489 人进入报名；受前序请求拖慢，报名发起跨度 7.8831 秒，**不是完整 1500 人在 1 秒内同时报名达标的证明**。首次 55 个 503 保留为错误，不用重试成功抹除。

## 对瓶颈的判断

1. **冷登录首先暴露连接路径问题。** 换公网出口仍失败，削弱了“只有租房线路有问题”的判断，但本轮还有本机 Mihomo 和 Wi-Fi 参与。没有双端抓包或绕过代理对照，不能确定具体丢包设备，更不能直接说腾讯云或公司运营商限制。
2. **报名阶段还存在服务端等待。** 提前登录轮主连接池累计等待 1084.67 秒 / 1544 次取连接（含重试），读池为 14.63 秒 / 3061 次。它们是累计值，不是单请求 P95。结合报名服务端 P95 3.0933 秒及 55 个依赖不可用 503，连接池等待值得优先定位；尚不能仅据此断言所有 503 的唯一根因。
3. **没有证据表明这轮耗尽了新服务器 200Mbps 带宽。** eth0 约 5 秒平均发送峰值 20.76Mbps、接收 6.09Mbps，不能排除更短尖峰或其他链路瓶颈。
4. 下一步可先做针对目标 IP 的临时代理旁路对照（保留其他日常代理和管理连接），再结合双端抓包定位连接损失；独立检查报名连接池等待与事务持有连接时间。本次只测试，没有实施这些修改。
