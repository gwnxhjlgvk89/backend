# v2 实施与验收台账

基线：后端 `6ad2b69`，前端 `de08256`；两个仓库均在 `develop`。

范围：本地隔离环境、权限、报名一致性、1500 人负载、实时通知、浅色校园界面、发布工具。
不自动执行生产部署、清理、提审、发布和 push。

## 验收门槛

- 1500 人 1 秒内提交：P95 ≤2s，P99 ≤5s；热门社团同样验证。
- 1500 人 60 秒内登录：P95 ≤2s；1500 WS 连接保持 30 分钟。
- 列表/状态稳态 P95 ≤300ms；通知 95% ≤1s；非预期 5xx/超时 <0.1%。
- 零超卖、零重复占位；3000 人超容量时可限流但不能错误记账。
- 最终 Linux 同配置压测、iOS/Android 真机、用户视觉验收均须独立记录。

## 提交要求

每个可验证阶段分别提交中文 commit；跨仓库记录配套 commit。没有变更不做空提交。
检查暂存差异、凭据、真实学生数据；只本地提交，不重写历史。

## 基线发现

- 管理接口没有鉴权、学生 ORM 全字段输出、日志含 Token。
- 同步数据库调用出现在 async 报名函数中；数据库连接池过大。
- 学生报名缺乏学生行锁；时间窗口硬编码；存在测试姓名豁免。
- WebSocket 进程内保存连接，4 worker 广播不共享；每 worker 重复更新缓存。
- 前端首页每 3 秒刷新 3 个接口；隐藏时定时器清理参数错误。
- 管理页全量轮询；前端明文记住密码；字体源文件约 127MB。
- 旧压测脚本导入即写数据库，禁止直接运行。
