# 密码存储与全量迁移

2026-09-28 按用户明确要求，运行时统一使用 `v2_users.password_plaintext` 保存密码，登录按 UTF-8 字节直接恒定时间比较；不保留 Argon2/bcrypt 兼容校验，也不再使用密码计算线程池。公开响应、预览、导出和日志不输出密码；前端仍只保存令牌和可选账号。

## 初始密码

所有已有账号（学生和管理员）迁移时统一重置为名单中的姓名原文，例如张三为 `张三`、吕布为 `吕布`。只去除姓名首尾空白，内部空格、中间点和英文大小写保持原样，不再转换拼音。默认账号规则不变：学生填写学号，管理员使用独立管理账号。

管理员新增学生/管理员和 Excel 导入留空初始密码时，按相同规则生成；也可明确指定初始密码。姓名为空或 UTF-8 超过72字节时拒绝自动生成，需核对姓名或明确指定密码。管理员修改姓名不会静默改变已有密码；重置需填写密码。所有迁移账号必须首次改密，用户自选新密码仍至少10字符且 UTF-8 不超过72字节。

## 全量切换

1. 维护窗口停止旧 API 和 worker，备份数据库并完成独立库恢复验证。
2. `alembic upgrade head`：0003 添加过渡列；0004 完成明文字段切换并删除 `password_hash`；0005 将全部账号重置为姓名原文、标记首次改密并递增会话版本。0005 也适用于此前已完成拼音迁移的库。每个重置步骤均先校验所有姓名再写入。
3. 启动新版 API/worker，核对账号数、新字段非空、旧字段消失以及登录/改密流程。所有旧令牌失效。

旧哈希不可逆，此处是重置，无法保留原密码。0004/0005 不支持 downgrade；旧后端不能读取新库。MySQL DDL 非事务化，迁移失败时保持维护，检查实际列/版本后再恢复或继续，不可启动新旧代码混用。失败重跑可能再次重置全部密码，必须在服务恢复前完成处理。上线后产生新报名时不能直接恢复旧库丢弃新数据。

旧表导入同样忽略旧密码哈希，按姓名原文重置并强制改密；旧源表和备份的保留/清理仍按发布清单单独处理。迁移前生成的旧格式待确认导入任务不兼容，需重新上传预览。新预览中的密码使用加密任务载荷，应用后清空。

合成压测/本地初始化脚本可显式设置统一测试密码，不能据此推断迁移后账号密码。Argon2/bcrypt 仅保留为历史单项基准脚本的开发依赖，生产运行无此依赖。历史容量报告代表旧哈希版本；本次仅功能回归，未重新压测，不宣称1500人容量通过。
