## 实测条件与结果

Ryzen5900X测试机，测试服务父cgroup `cpu.max=400000 100000`、`memory.max=4294967296`，禁Swap，HTTPS出口50Mbps；各服务原内存上限不变（合计2948MiB）。4个API进程，每进程密码计算并发3。其余应用代码和配置保持原样。CPU配额不是同规格腾讯云虚拟机，部分rootless网络辅助进程仍在配额外。

登录客户端超时固定10秒，超时计入P95；这些数字不是全部请求最终完成需要的时间。实际客户端开始跨度2.02秒以上，未达到计划的0.6秒突发，也未达到1秒门槛；在流量已被摊开的情况下仍有大量超时。登录后报名仅为成功进入的子集，不能用其较低报名延迟宣称1500人集中报名达标。

## CPU证据

对已完成三轮报告中首末资源采样的各服务cgroup累计CPU时间取差：API 173.743秒、MySQL 12.375秒、Nginx 7.429秒、Redis 1.015秒、worker 1.758秒。API占这五个服务CPU消耗约88.5%。该占比涵盖采样窗口内的准备/登录/后续请求，不是Argon2函数CPU占比，也不包含配额外网络辅助进程。容器瞬时输出中的生命周期平均CPU百分比不用于热点结论。

父cgroup在采样窗口内1446个周期中386次受到CPU配额节流；无OOM。三轮密码执行名额等待均值5.51/4.84/4.56秒；已执行的Argon2校验平均墙钟耗时72.88/77.82/82.13ms。后者包含线程被抢占或受节流的时间，不是纯CPU计时。
