# 单核性能实测对比（2026-09-28）

用户明确授权先在腾讯云线上服务器做单核短测，再测局域网服务器。两台测试前均空闲；只运行合成CPU计算，没有请求业务接口、读取业务数据或修改服务配置。

| 工作负载（三轮中位数） | 腾讯云 EPYC 7K62 | 测试机 Ryzen 9 5900X | 测试机/线上吞吐 |
|---|---:|---:|---:|
| 整数依赖运算循环 | 3.225亿次/秒 | 4.806亿次/秒 | 1.49倍 |
| Argon2id：7MiB、5轮、并行度1 | 51.71次/秒 | 87.28次/秒 | 1.69倍 |
| 对应单次Argon2平均计算时间 | 19.34ms | 11.46ms | 测试机耗时约为线上59% |

## 方法及原始证据

- 同一份C源码在生产机以 `gcc -O2 -Wall -Wextra -Werror -march=x86-64` 编译一次；该二进制与线上现有 `libargon2.so.1` 复制到测试机独立临时目录，通过 `LD_LIBRARY_PATH` 加载，不安装或替换系统库。
- 两台二进制与Argon2库的SHA256分别完全一致，合成密码计算输出一致。Python仅安排测试和读取系统状态，不参与计时内的计算；两台Python版本差异不作为CPU工作负载。
- 每台固定一个逻辑CPU（线上CPU0、测试机CPU1），单进程单线程，nice=19；两项负载分别3轮，每轮约2秒，每轮后休息1秒。每台实际计算约12秒，基准进程25秒超时上限。
- 测试前校验负载、可用内存和空闲CPU；两台每轮CPU时间/实际时间约100%，未见明显调度等待。该窗口整机steal占比均0%；这不保证云机其他时段没有争用。
- 三轮Argon2线上51.45/51.96/51.71次每秒，测试机87.19/87.28/87.29次每秒。整数线上3.222/3.225/3.225亿次每秒，测试机4.808/4.806/4.798亿次每秒。
- 测试结束已清理两台服务器的本次临时程序/库文件；线上随后CPU约99%空闲、Swap使用为0。未安装软件、重启或调整业务服务。
- 原始记录：[线上](../reports/single-core-production.json)、[测试机](../reports/single-core-test-host.json)、[对比汇总](../reports/single-core-comparison.json)。源码：`scripts/benchmark_single_core.c`；执行与元数据采集：`scripts/run_single_core_probe.py`。

## 对容量判断的意义

测试机在本次单线程计算上显著快于线上，不能以测试机4CPU配额代表线上4 vCPU，更不能把之前16配额下的1500人通过结果称为4核4GB通过。

这是单线程微基准，不是完整登录、1500并发、多核扩展、数据库或公网带宽测试。整数循环只代表一种计算模式；Argon2属于内存密集型计算，本次使用固定合成密码与盐，参数与新版一致，但未加载应用的Python绑定及其打包库、未测旧bcrypt升级。单线程轻载时的缓存和频率也不同于多线程高峰。

因此1.49/1.69倍只能作为对应工作负载的实测差距，不能据此直接得出需要多少云vCPU、把登录4.2秒乘1.69作为线上延迟，或宣称对完整服务器做了等价模拟。系统内核、libc和虚拟化环境差异仍属于本次实测环境。
